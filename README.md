# C言語を使った、コンピューターサイエンス学習

C言語を使って、メモリ管理、ポインタ、コンピュータの内部構造の理解などを学ぶため

## ソースコードが実行するまで。
ソースコードを実行するまでにいくつかの手順がある。
まず前提として、コンピュータはバイナリ(0と1)でしか理解できない。

## コンパイル
- コンバイラというプログラムでソースコードを受け取り、マシンコード(0と1)を生成する。
- コンバイラは、ソースコードをマシンコードに変換するプログラム。
- ソースコードをコンピュータに直接理解できるためにコンパイルをするためのプログラム。

## コマンド実行後の流れ
- makeコマンドでコンパイラにアクセスする(make hello)
- 作りたいプログラムを入力(./hello)を入力し、helloを呼び出す。
- 自分のコンピュータの中にあるhelloのファイルを検索
- hello.cファイルにある、「hello, world」が出力

## なぜ、再度コンパイルをしなければならないのか？
- C言語がそういうものだから。
- 当時は非常に慎重だった。パフォーマンス優先。
- 今はコンパイルを主導しなくても自動でやってくれるが、これらの過程がどのようになっているのかを理解するため
- 変更したソースコードなどは古いファイルに反映されないから、新しいソースコードや変更したソースコードをコンピュータに伝えるため。

## データ型
- bool 真偽値 真または偽 true false  1byte
- char 1文字 aや1のような単一  1byte
- double 浮動小数点数。小数点以下の何桁かを伴う実数。  8byte
- float doubleよりもさらに多くの桁数を持つことができる。  4byte
- int C言語では３２ビット(40億を超える数まで扱える)  4byte
- long 64ビット  8byte
- string 文字列 複数の文字として扱う  ?byte

変数にint型の整数の場合、C言語ではこれを正数に変換して小数点以下を全て切り捨ててしまう。
計算は正しく行われるが、浮動小数点数や小数点以下の数字を正数に収めることができないため、
小数点以下の数字すべて失われてしまう。
整数部分の整数にしか収めることができない。

## コンピュータの能力の限界
- コンピュータには限られたRAM、ハードウェア、ビット数しかない
- ３２ビット６４ビットといった限られた数のビットしか使わないから、かなり大きい数まで正確に数えることはできる。
- 無限に大きな数まで、正確に数えることはできない。(浮動小数点数に限らず、正数でも)
  
## コンパイル
- makeコマンドは、コンパイルを行う処理を自動化してくれるライブラリ
- 本来なら、裏側ではclangコマンドを使ってコンパイルを実行します
- ソースコードのマシンコードへのコンパイルは、次のいくつかの小さなステップの構成になっている。
  - 前処理
  - コンパイル
  - アセンブル
  - リンク
- 前処理 #includeのように#で始まる行が含まれる。
- clangはこれらのヘッダファイルの内容をプログラムに置き換える。
```
#include <cs50.h>
#include <stdio.h>
 
int main(void)
{
    string name = get_string("What's your name? ");
    printf("hello, %s\n", name);
}
```
これを前処理では以下のようになる
```
...
string get_string(string prompt);
int printf(string format, ...);
...
 
int main(void)
{
    string name = get_string("Name: ");
    printf("hello, %s\n", name);
}
```
コンピュータは何が起きているのかわかるように、コードの中で全ての関数を定義している。
コンピュータは、先にそのファイルの関数が何をしているのかを一番上で知る必要がある。
つまり、一番下に関数を実装するとコンピュータは、そのファイルの処理は何をするのかを気付けなくなる。


- コンパイルでは、C言語のソースコードを取得し、アセンブリコードと呼ばれる別のタイプに変換する。(コンピュータに適した言語に変換される)
- アセンブルとは、アセンブリコードを最終的に機械語(0と1)に変換する。
- アセンブリコードを取得し、それをアセンブルしてバイナリ形式(０と１)のマシンコードで、コンピュータのCPUが直接実行する。
- 最後は、実際にプログラムのバイナリと結合するリンクで、マシンコードであるa.outまたはhelloという一つのバイナリファイルになる。
- コンパイルされたマシンコードがすでにインストールされ、それらを検索して使用するようにclangやmakeが設定されいている。
- ソースコードからアセンブリコード、マシンコードへの変換、そして使用したライブラリとのリンクというプロセスを自動化してくれる、makやclang。

## メモリ
- RAM(Random Access Memory)は、プログラムが実行されている間に格納される場所(ファイルを開いているときなど)
- RAMは揮発性のため、PCの電源を切ったり、バッテリーが切れたり、PCのプラグが抜けたり、携帯電話が壊れたりすると、データを失う。
- メモリの容量が１０億２０億だろうともっと少なかろうとある数のバイトがあるとすれば、これらのバイトすべてに番号をつけることができる。
- charなら、１バイトでメモリのどこかに正方形で格納されている。4バイトのInt型変数を格納している場合、4つの正方形をすべて使用することになっているかもしれない。
- コンピュータのメモリのこれらのバイトに全て変数の値が格納される


## 配列
- メモリ内では、変数を次々に連続して格納し、ループを使用してより簡単にアクセスできる。
- 連続して格納された値のリストを配列と呼ぶ。
- int scores[0]; この記法を、ブラケット記法という。
